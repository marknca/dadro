Requirements

This re-write was designed to run on Linux, macOS, and Windows. It's written using the Python programming language and uses a framework called Qt for the user interface. Both of these are freely available for this use case on a broad set of supported platforms.

Most users will be running this on a Linux distribution given the primary use case of running on a shop environment. For Raspberry Pi systems, use the system Python and Qt packages:

sudo apt update
sudo apt install python3-pyqt6 python3-serial qt6-wayland

The Pi setup includes the required Python bindings and serial library. Launch it with system Python; see the Raspberry Pi installation notes for desktop and Qt plugin troubleshooting. Other distributions may use different package names.

On macOS, use Homebrew to get up and running quickly with:

brew install python3

For a virtual-environment installation, run these commands from the repository root or the release directory. The manifest installs PyQt6 and pyserial together:

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r REQUIREMENTS.txt

For Windows commands and platform-specific details, follow Install and launch in the user guide.

Running the program

From the repository root, launch the release snapshot using the Python environment where its dependencies are installed:

python3 -B release/src/app.py

From inside the release directory, use python3 -B src/app.py. On the Pi system-package setup, use /usr/bin/python3. The app opens machine setup on first run; the user guide walks through connecting the scales.

History

My first introduction to the YADRO project was in 2008. My father bought the hardware kit to set up scales on his 3-axis mill. Since then, he added a YADRO kit to his lathe and has been using the hardware+software regularly with minimal issue for over 18 years.

The YADRO project was launched in 2006 and went offline sometime in the fall of 2014. The Wayback Machine from the Internet Archive has a number of snapshots from when the project was active, but this last one is probably the most useful.

You can navigate the original project website through the Wayback Machine or via the cached copy in this repo under yadro-de.

The short version of the project is that it's a small hardware device that reads and powers up to 4 scale inputs (3 axes + 1 quill). Paired with its DOS-based software, it provides a simple, robust digital read out (DRO) for lathes and mills.

Original software

My father's original setup was using an old 486sx laptop with a TFT screen and running the software off of a bootable 3.5" floppy disk. Believe it or not, this was a reasonably reliable setup. It worked for years and when—once or twice—there was an inevitable hardware failure, a replacement laptop was easy enough to get from the local electronics recycler for under $80 CDN.

As you might guess, a major challenge was the floppy disk. A fragile, spinning PET plastic disk with a ferromagnetic oxide coating that's read by two electromagnetic heads is not a piece of equipment that you want running next to a lathe or a mill!

All of those little metal shavings eventually find their way into either the laptop, the floppy disk drive, or the actual floppy disk.

If you are still using a floppy disk-based system, there is a bootable disk image and the full boot disk contents in this repo.

Original hardware

Nick's website has a complete breakdown of the hardware. From how to build the PCB to the complete circuit diagram to how to debug the scales. There is also a complete schematic for the wire protocol that the software interprets.

The hardware is extremely well designed and the only reason to consider replacing it is if your current scales fail and you decide to go in a different direction with their replacements.

Modernizing the project

To replace the floppy disk-based system, I first tried to virtualize the DOS software on top of Linux. Specifically, I tried to get it running efficiently under DOSBox-X, DOSEMU2, and 86Box.

Each of these was capable of running the basic software, but inevitably ran into challenges with "fast mode" where the reads from the serial port were near-constant.

Why? This is a question I wrestled with for a while. Even the smallest of Raspberry Pi Zero absolutely eclipses the 486 hardware the project started on. Even with the overhead of running a native operating system (Linux) and then emulating another (DOS) while converting CPU instructions from x86 to ARM should leave enough computing power to run hundreds of DRO instances.

But things rarely work the way the spec says.

At the heart of the matter is the challenge with the serial port over USB adapters that are inevitably required to connect to the YADRO hardware. This adds some additional hardware limitations (the adapters are not designed with this use case in mind) that conflicted with the original DOS programming.

It is possible to get modern replacements to create a direct serial port connection wired to a Raspberry Pi, but that didn't seem worth the effort.

There were just too many moving pieces to ensure this was a reliable implementation.

Reverse engineering the original software

With the complete documentation and working code, this project started by directing OpenAI's Codex using GPT6-Astra to reverse engineer and document the complete functionality of the existing YADRO software.

That work resulted in a quite comprehensive set of documents describing how the hardware and DOS application interacted and how the work was done. The key information from that effort has been cleaned up and imported here as /docs/yadro-dos-commands.html. This page lists all of the basic and macro commands available in the original software and explains what they do.

That document is the basis for the new application code. Since we had a reference that was built from and proven by the original code, we were more confident in the outcome of a rewrite.

This was enough that we were able to write a quick proof of concept by hand. This quick test confirmed that the issue was the DOS-based software and the serial-to-USB adapter, the new code easily read at full speed from the YADRO through a serial-to-USB adapter with minimal hardware.

Rewriting the code and updating the user interface

The protocol to interpret the data from the YADRO hardware was the easiest part of the project. With complete documentation and the reverse engineered original software, Codex was able to write a new parser in Python that required only minor adjustments after testing with real hardware (/release/src/yadro_protocol.py).

Efforts then moved to modernizing the user interface. While the original DOS interface now comes across as very retro, it doesn't provide a great experience on modern hardware.

The new implementation is designed with a more modern 1920x1080 resolution (1080p) in mind. It'll scale and adjust to other resolutions, but the expectation is that most low-cost displays will be operating at this resolution. By aiming for this common 16:9 aspect ratio, the interface focuses on displaying the scale readings in a clean, bold control that you can see clearly from a distance.

Multiple macros from the original YADRO have been condensed into more intuitive functionality. This is now possible because the software is working with a graphical user interface and not a simple text-based one.

Simple keyboard navigation has been maintained and the entire application can be navigated with the four arrow keys, enter, and /...all conveniently located on a standard number pad.

The specifics of the new software are described in depth in the documentation. You can start reading that here.
